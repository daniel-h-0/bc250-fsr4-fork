# V3 technical notes — EXP-042B

V3 is the result of the post-v2 FSR4 shader-lowering investigation on AMD BC-250 / GFX1013.

## Runtime progression

Same Cyberpunk 2077 scene, FSR 4.1.1 INT8, FG off:

- EXP-035B2: 58 FPS
- EXP-040E: 59 FPS
- EXP-042A: 61 FPS
- **EXP-042B: 63 FPS**

EXP-042B is therefore the V3 runtime golden.

## Key discoveries

### Native signed packed dot is not usable

A direct hardware probe of `v_dot4_i32_i8` returned 0 for a case whose correct dot result is 70. V3 never advertises or executes that path.

### Wrapper fusion matters

FSR4 emits explicit `iadd(0, OpSDot)` forms. Fusing through that wrapper before the ordinary software fallback exposed the real accumulator and produced the B2 breakthrough.

### Register pressure matters more than instruction count alone

Aggressive MAD24 chains often reduced instruction count/static throughput cost while dropping occupancy from 6 to 4 waves. Two shorter dependency chains were better for pressure-sensitive families.

### Deferred SDot fixed the pathological ED7 shader

Allowing remaining SDot operations to survive one optimization round before software lowering radically changed ED7's live-range/spill behavior:

| metric | pre-V3 path | V3 |
|---|---:|---:|
| VGPR | 256 | 168 |
| VGPR spills | 1314 | 0 |
| scratch bytes | 320512 | 0 |
| waves/SIMD | 4 | 6 |
| instructions | 21750 | 16904 |
| inverse estimate | 23224 | 24825 |

The inverse estimate alone predicts a small regression, but the actual spill/occupancy improvement is much more important for runtime.

### Full 64-shader audit

EXP-042B vs B2:

- common shaders: 64
- changed: 13
- lower inverse estimate: 12
- higher inverse estimate: 1 (ED7, explained above)
- new VGPR spill regressions: 0
- lower resident-wave regressions: 0

## V3 implementation summary

The complete source delta is in `bc250-fsr4-v3.patch`.

It includes:

1. BC-250/GFX1013 base compatibility/compute-queue changes used in the tested build.
2. ACO support for the signed i24 MAD form used by the fallback.
3. FSR4 wrapper fusion and constant/data signed-dot lowering.
4. GFX1013-only dense-reduction lowering for empirically safe reduction forms.
5. Two-chain lowering for pressure-sensitive dense forms.
6. One deferred NIR optimization round for remaining GFX1013 compute SDots, followed by restoration of the real capability set and software lowering.

The temporary `has_sdot_4x8=true` value exists only inside NIR optimization to defer lowering. It is restored before the real fallback/code generation. It does **not** advertise hardware support and does **not** emit the broken native packed-dot instruction.

## Precompiled release

The GitHub release ships the exact EXP-042B runtime-tested RADV `.so`, renamed to `libvulkan_radeon.so` inside the archive.

The release package is intentionally per-game/per-user. It is not a distro Mesa replacement.

The tested binary dynamically links the CachyOS/Arch LLVM 22.1 stack, so the installer validates dependencies and directs incompatible distributions to the Docker source-build path.
