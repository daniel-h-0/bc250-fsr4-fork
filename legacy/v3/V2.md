# BC-250 FSR4 v2 — EXP-028 selective signed DP4A lowering

This branch contains the second BC-250 / GFX1013 FSR4 optimization and corresponds to the tested EXP-028 compiler strategy.

## Base

- Mesa 26.2.0
- BC-250 GFX1013 compute-queue base fix
- optional `RADV_GFX103=1` override (off by default)
- FSR4 signed 4x8 software DP4A optimization

Mesa 26.2 already uses `imul24_relaxed` for the software signed 4x8 dot-product fallback. Global reassociation is very effective on most FSR4 kernels, but corpus profiling found pathological shader families where applying it globally greatly increases register pressure and spilling.

## EXP-028 change

For `sdot_4x8_iadd`:

- constant accumulator `c` -> keep Mesa's balanced four-product sum
- non-constant accumulator `c` -> use the right-reassociated sum

The constant-specific algebraic rule is intentionally placed before the generic rule in `nir_opt_algebraic.py`.

This preserves the major wins from reassociation while avoiding the worst spill regressions discovered in a 64-shader FSR4 capture.

## Reproducible source/build configuration

The v2 builder mirrors the Meson options used for EXP-028:

    -Dbuildtype=release
    -Dwrap_mode=nodownload
    -Dvulkan-drivers=amd
    -Dgallium-drivers=radeonsi
    -Dllvm=enabled

It deliberately does not add the old `-march=x86-64-v3 -mtune=znver2` host tuning flags.

The Docker build uses Fedora 44 and installs the Mesa dependencies needed for the same feature configuration. A rebuilt binary is expected to reproduce the source and Mesa configuration of EXP-028, but its SHA256 is not guaranteed to equal the known-good local hash because compiler/LLVM/library versions inside the build environment may differ from the original CachyOS host.

The persistent `.build/` cache is explicitly reconfigured on each run, preventing an older v1 Meson configuration from being silently reused.

## Patch order

The patched variant applies, in order:

1. `v2-patches/0001-gfx1013-compute-queue-fix.patch`
2. `bc250-fsr4-v2-selective-sdot.patch`
3. `v2-patches/0003-radv-gfx103.patch`

The optional GFX10.3 override remains disabled unless `RADV_GFX103=1` is explicitly set at runtime.

## Build

From the `v2` branch:

    ./build-anywhere.sh

Then:

    ./setup.sh
    ./check.sh

Runtime verification:

    ./run-bc250-fsr4.sh vulkaninfo --summary

Expected result: RADV, Mesa 26.2.0, AMD BC-250 / GFX1013.

For Steam, use the ICD generated by `setup.sh`, for example:

    VK_DRIVER_FILES=/absolute/path/radv-bc250-fsr4.json WINEDLLOVERRIDES="version=n,b" %command% --launcher-skip

Do not install this experimental RADV library system-wide.

## PR #1

Useful robustness ideas from PR #1 by `higorprado` were incorporated into the v2 packaging helpers: missing-binary checks, safer ICD generation, argument validation, and dependency/JSON validation via `check.sh`.

The PR's global dot-product reassociation patch was **not** merged into v2. EXP-028 keeps the selective signed lowering described above because shader-corpus testing showed that global signed reassociation causes severe spill regressions in specific FSR4 kernels.

The PR's INT8 dot-product benchmark was ported as a diagnostic tool with corrections for Vulkan feature enabling and memory-type selection. Historical benchmark results from the PR remain separate from EXP-028 performance claims.

## Status

Experimental, but now validated both as the original EXP-028 runtime build and through a clean-clone GitHub `v2` rebuild on BC-250. EXP-028 is the current known-good performance baseline for this project.
